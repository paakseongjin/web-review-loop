## 먼저 알아둘 내용

- **현재 판단:** <범위에 맞는 판정 또는 제한된 리뷰라는 설명>
- **확인한 범위:** <페이지·기능·코드·환경과 날짜>
- **사용자에게 생길 수 있는 일:** <확인된 영향과 아직 확인되지 않은 영향을 구분>
- **지금 할 일:** <우선순위가 높은 조치와 이유; 없다면 확인 범위 안에서 발견되지 않았다고 명시>
- **미확인 사항:** <실행하지 못한 검사, 원인, 의미>

## 우선순위별 검토 사항

각 항목마다 비개발자가 선택할 수 있도록 작성:

- **상태와 우선순위:** <확인된 문제 / 가능성 / 개선 제안; 긴급도와 이유>
- **무슨 일인가요?** <상황, 방문자 또는 운영자에게 미치는 영향>
- **어떻게 확인했나요?** <페이지·단계·관찰 결과 또는 파일·위치·데이터 흐름; 확인하지 못한 영향>
- **판단 근거:** <적용되는 표준의 조항 또는 해당 버전 공식 문서 URL, 확인 날짜, 적용 조건과 예외. 근거를 확인하지 못했다면 명시>
- **어떻게 고치나요?** <구체적인 방향, 기대 효과, 호환성·비용·변경 위험. 대안이 있으면 제시>
- **수정 및 검증:** <수정 여부, 변경 후 결과와 미실행 검사>

## 검사 범위와 결과

<실행한 도구·버전·명령 또는 URL·환경·결과; SKIPPED 및 UNVERIFIED 사유를 명시. 경고는 검증 전 확정 문제로 취급하지 않음. 페이지·기기 폭·역할·상태별 실제 확인 범위와 누락을 기록. 성능은 도구·조건·현장/실험실 구분과 가능한 경우 백분위 포함.>

## 기술 상세와 안전한 복구

<개발자에게 전달할 파일·줄·재현 단계 및 민감정보를 제거한 증거. 수정한 경우 해당 변경만 되돌리는 방법. 수정하지 않았다면 수정 없음이라고 표기. 접근성 자동 검사는 일부만 확인하며 인증이나 전수검사가 아님을 명시.>
